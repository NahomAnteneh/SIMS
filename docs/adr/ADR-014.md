# ADR-014: Search Indexing Model and Compiler Architecture

## Status
Proposed

## Context
Users require diverse search modalities across the virtual infrastructure:
1. **Exact Identifier Lookup:** IP address, MAC address, BIOS UUID, instance UUID, VM name.
2. **Substring & Fuzzy Match:** Partial hostname, operating system name, annotation/description text.
3. **Hierarchy Scoping:** All VMs under folder path `Datacenter/Production/*`.
4. **Network & VLAN Filtering:** Subnet containment, VLAN range intersection.
5. **Compound Boolean Filters:** `cluster = 'Prod-01' AND power_state = 'poweredOn' AND cpu_count >= 8`.

Sending every query through a single generic `WHERE ... LIKE '%q%'` causes full-table sequential scans that exhaust database I/O.

## Decision
Implement a multi-tier search compiler paired with specialized PostgreSQL index types:
1. **Trigram Indexing (`pg_trgm`):**
   - Create GIN trigram indexes on text fields: `CREATE INDEX idx_vms_name_trgm ON virtual_machines USING gin (name gin_trgm_ops)`.
   - Enables fast regex and substring matches (`ILIKE '%app%'`).
2. **Hierarchical Indexing (`ltree`):**
   - Create GiST indexes on folder paths: `CREATE INDEX idx_vms_folder_path_gist ON virtual_machines USING gist (folder_path)`.
3. **Compound B-Tree Indexes:**
   - Indexes on frequent filter combinations: `(vcenter_id, cluster_id, power_state)`.
4. **Typed Search Compiler:**
   - The Query API parses search syntax (e.g. `name:web* vlan:100 status:poweredOn`) into an Abstract Syntax Tree (AST).
   - Validates fields against an allowlist before compiling into parameterized SQL with targeted index conditions.

## Consequences
### Positive
- Sub-50ms search latency on multi-million row inventories without an external search cluster.
- Prevents SQL injection by validating fields at the AST parser stage before SQL generation.
- Full support for complex boolean queries and prefix/suffix matching.

### Negative / Trade-offs
- GIN trigram indexes consume significant disk space and have write overhead during high-volume ingestion.
- Staging table bulk updates (ADR-004) must batch index updates to avoid write stalls.

## Alternatives Considered
- **PostgreSQL Full-Text Search (`tsvector` / `tsquery`):** Tokenizes by dictionary words, which performs poorly on technical machine identifiers with dots, dashes, and hexadecimal strings (e.g. `vm-prod-db01.corp`). Trigram indexing (`pg_trgm`) is far superior for infrastructure names.

# ADR-011: Virtual Machine Identity and Deduplication Model

## Status
Proposed

## Context
Tracking virtual machines reliably across their full lifecycle in a multi-vCenter environment is complex due to various vSphere behavioral edge cases:
1. **Moref Reuse:** A Managed Object Reference (e.g. `vm-1234`) is only unique within a single vCenter at a given point in time. When a VM is deleted, vCenter may recycle its Moref for an unrelated new VM.
2. **BIOS UUID (`config.uuid`):** Non-unique across vCenters; cloning a VM or deploying from a template often duplicates the BIOS UUID unless sysprepped or regenerated.
3. **Instance UUID (`config.instanceUuid`):** A 128-bit UUID assigned by vCenter that is intended to be globally unique to that specific virtual machine instance.
4. **Cross-vCenter vMotion (xvMotion):** When a VM moves from vCenter A to vCenter B, its Moref changes completely, but its `instanceUuid` is usually preserved.

## Decision
Adopt a composite natural key and surrogate identity model:
1. **Primary Database Identity:** Synthetic UUID (`id UUID PRIMARY KEY DEFAULT gen_random_uuid()`).
2. **vCenter Scoped Key:** Unique constraint on active VMs: `(vcenter_id, moref)` where `deleted_at IS NULL`.
3. **Global Correlation Key:** Index on `instance_uuid` (`config.instanceUuid`).
4. **Soft Deletes:**
   - When a VM is deleted, set `deleted_at = NOW()`.
   - If a new VM appears with the same `(vcenter_id, moref)` but a different `instance_uuid`, treat it as an independent VM entity, preserving the historical record of the retired VM.
5. **xvMotion Handling:**
   - Link the source and target VM records via matching `instance_uuid` and historical relocation events.

## Consequences
### Positive
- Prevents identity collisions when vCenter recycles Morefs.
- Correctly reconciles cross-vCenter migrations via `instance_uuid`.
- Historical audit logs and deleted VM records remain queryable without corrupting active inventory.

### Negative / Trade-offs
- Queries targeting active VMs must explicitly filter by `deleted_at IS NULL`.
- Reconciling duplicated `instance_uuid`s resulting from improper VM cloning requires a disambiguation strategy.

## Alternatives Considered
- **Moref as Primary Key:** Fails immediately upon Moref recycling and across multi-vCenter deployments.
- **BIOS UUID as Primary Key:** Fails due to prevalent UUID duplication across cloned templates in enterprise environments.

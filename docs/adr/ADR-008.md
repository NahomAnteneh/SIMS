# ADR-008: Collector Worker Lease Model via PostgreSQL

## Status
Proposed

## Context
The platform collector tier operates as a distributed fleet of worker instances capable of monitoring multiple target vCenters. To prevent split-brain conflicts, duplicate polling, and race conditions, exactly one active worker must hold the collection lease for a given vCenter target at any given time.

Traditional distributed consensus solutions require deploying and operating an external consensus cluster such as HashiCorp Consul, Apache ZooKeeper, or etcd.

## Decision
Implement leader election and target assignment using a PostgreSQL-backed lease table (`collector_leases`) with heartbeat timestamps and row-level locking (`pg_try_advisory_lock` or `SELECT FOR UPDATE SKIP LOCKED`):
- Each collector periodically claims or renews its lease on a target vCenter by updating `lease_until = NOW() + INTERVAL '30 seconds'` and sending heartbeats every 10 seconds.
- If a collector crashes or partitions from PostgreSQL, its lease expires automatically after 30 seconds.
- Standby collectors continuously scan for expired leases and immediately acquire orphaned targets.

## Consequences
### Positive
- Zero external coordination dependencies: no Consul, etcd, or ZooKeeper to deploy or maintain.
- Fencing is strongly consistent under PostgreSQL ACID transactions.
- Operational visibility: operators can inspect which collector instance owns which vCenter directly by running `SELECT * FROM collector_leases;`.

### Negative / Trade-offs
- Collector fleet availability depends on PostgreSQL connectivity.
- Lease expiration introduces a failover delay (e.g. 30 seconds) before a standby collector takes over an orphaned vCenter.

## Alternatives Considered
- **etcd / Consul:** True distributed consensus with Raft, but introduces significant operational overhead and management complexity.
- **Kubernetes Leader Election:** Works well inside Kubernetes via Lease API, but tightly couples the application to Kubernetes and precludes running collectors on bare-metal VMs or Docker Compose.

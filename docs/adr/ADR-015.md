# ADR-015: Authentication and Inventory Visibility Scoping Model

## Status
Proposed

## Context
In multi-tenant or large enterprise environments, different user groups require distinct access levels:
- Platform Admins: Full visibility and collector management.
- Application Teams: Read-only search visibility restricted to their specific datacenters, folders, or clusters.
- Automation Service Accounts: Programmatic access with scoped search permissions.

Hardcoding user accounts or building custom password storage within the platform creates security liabilities and maintenance burdens.

## Decision
Adopt standard OpenID Connect (OIDC) authentication paired with Role-Based Access Control (RBAC) and inventory visibility scopes:
1. **Authentication:**
   - Delegate user authentication to an enterprise OIDC Identity Provider (e.g. Okta, Keycloak, Microsoft Entra ID).
   - The Query API validates incoming JSON Web Tokens (JWTs) using standard JWKS public keys.
2. **Authorization & Roles:**
   - Define discrete system roles: `PlatformAdmin`, `InventoryReader`, `AuditViewer`.
3. **Visibility Scopes:**
   - Support scope constraints at query time: a user's token claims or assigned role can limit queries to specific `vcenter_id`s, `datacenter_id`s, or `ltree` folder subtrees (`folder_path <@ user_allowed_path`).
   - The Query API search compiler injects mandatory tenancy scope predicates into every generated SQL query.

## Consequences
### Positive
- Zero credential storage in the application database: eliminates risk of leaked passwords or hashes.
- Seamless single sign-on (SSO) and centralized access revocation via enterprise IdP.
- Fine-grained multi-tenancy enforced at the database query level.

### Negative / Trade-offs
- Local offline development requires a mock OIDC provider or local development bypass flag.
- Adds JWT validation latency and token expiration refresh handling on the client.

## Alternatives Considered
- **Local User Database with bcrypt:** Unacceptable for enterprise deployments requiring centralized directory integration and MFA.
- **mTLS Only:** Strong for service-to-service communication, but impractical for web browser interactive users.

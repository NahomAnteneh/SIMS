# ADR-010: Event Replay and Deduplication Semantics

## Status
Proposed

## Context
In addition to state changes streamed by PropertyCollector, vCenter emits discrete operational events (e.g. `VmCreatedEvent`, `VmPoweredOnEvent`, `VmMigratedEvent`, `VmRemovedEvent`) accessed via `EventHistoryCollector`.

PropertyCollector alone can miss intermediate state transitions (e.g., a VM is powered on and immediately powered off between polling intervals). Events capture these transitions, but network disruptions or collector restarts can lead to gaps or duplicate reads.

## Decision
Decouple `EventHistoryCollector` processing from PropertyCollector and implement idempotent event replay:
1. **Deduplication Key:**
   - Every event in vCenter has an integer `Key`, a `ChainId`, and a timestamp.
   - Events are persisted to `vcenter_events` with a unique constraint on `(vcenter_id, event_key)`.
2. **Lookback Buffer Overlap:**
   - Upon reconnecting or resuming after a disconnect, the collector queries events starting from `last_seen_event_time - 5 minutes` (the overlap buffer).
   - Duplicate events retrieved during the overlap window are safely ignored on insert via `ON CONFLICT (vcenter_id, event_key) DO NOTHING`.
3. **Event Watermarking:**
   - The collector advances an event high-watermark only after successful database transaction commit.

## Consequences
### Positive
- Zero event loss across transient network dropouts and collector restarts.
- Strict idempotency: replaying events does not corrupt database state or duplicate audit log entries.
- Clear audit trail of who changed what, when, and on which vCenter.

### Negative / Trade-offs
- vCenter event retention is finite (typically 30–90 days). If a collector is disconnected longer than the retention window, events are permanently lost and full snapshot re-hydration is mandatory.

## Alternatives Considered
- **Strict Single-Pass Stream (No Overlap):** Polling strictly from `last_seen_key + 1`. Fails because vCenter event keys can occasionally arrive slightly out of sequence across clustered vCenter nodes.

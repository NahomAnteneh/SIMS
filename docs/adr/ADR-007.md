# ADR-007: No Mandatory gRPC (REST/JSON with OpenAPI 3.1)

## Status
Proposed

## Context
Microservice architectures often debate gRPC (HTTP/2 with Protocol Buffers) versus REST/JSON over HTTP/1.1 or HTTP/2. gRPC provides compact binary serialization and strictly generated client stubs.

However, web browsers cannot natively initiate standard gRPC calls without a proxy layer (such as Envoy with `grpc-web`). Furthermore, querying inventory from curl, CI pipelines, shell scripts, and third-party monitoring platforms becomes significantly more cumbersome when binary serialization is required.

## Decision
Adopt standard REST/JSON over HTTP as the primary API protocol, governed by an explicit OpenAPI 3.1 specification.
- The Query API and Collector management interfaces expose RESTful JSON endpoints.
- Browser UI (Next.js) directly communicates with the Query API using standard `fetch` without intermediary proxies.
- gRPC is not prohibited for future internal inter-service worker streaming if high-throughput requirements dictate it, but it is not mandatory or introduced in v1.

## Consequences
### Positive
- Universal compatibility: accessible directly by browsers, curl, Postman, Python, Bash, and all standard HTTP tools.
- Simplified frontend integration: native Next.js server and client components can interact directly without custom WASM or grpc-web proxies.
- Straightforward observability: HTTP headers, standard access logs, and load balancer metrics work out of the box.

### Negative / Trade-offs
- JSON serialization and parsing is computationally more expensive and consumes more bandwidth than binary Protobuf serialization.
- Lack of bidirectional streaming out of the box (streaming search results will use Server-Sent Events or chunked JSON).

## Alternatives Considered
- **gRPC + grpc-web + Envoy:** Adds an entire proxy infrastructure tier solely to allow the browser frontend to communicate with Go backend services.
- **GraphQL:** Flexible for client querying, but adds complex query complexity analysis, caching hurdles, and execution overhead.
